# Reporting Layer

## Purpose
The Reporting layer consolidates all computed analyses, reproducibility metadata, and visualization assets into publishable, standardized documents. It acts as the final output phase of a BioZig pipeline.

## Directory Layout
- `html/`: Interactive HTML report generation.
- `latex/`: Academic LaTeX manuscript formatting.
- `manuscript/`: Unified text/figure manuscript orchestration.
- `markdown/`: GitHub-flavored Markdown outputs.
- `pdf/`: Standalone document generation.
- `supplement/`: Generation of supplementary data tables and figures.

## Public Types
- `reporting.Report`
- `reporting.Section`

## Public APIs
- `reporting.Report.init()`
- `markdown.exportMarkdown()`
- `html.exportHtml()`
- `latex.exportLatex()`
- `pdf.exportPdf()`

## Serialization Format
The layer takes the binary definitions of `Report` and translates them exclusively into human-readable text formats (HTML, Markdown, TeX).

## Memory Model
The `Report` struct is an orchestration container; it borrows slices of figures, tables, and text (`[]const Section`, `[]const Figure`). It does not allocate or duplicate the massive strings generated by the Visualization layer, acting merely as a zero-copy pointer aggregation.

## Determinism Guarantees
- Exporters produce bit-exact string outputs for a given Report state.
- All internal metadata (like timestamp and hardware) is appended automatically via the `core.reproducibility.ReproducibilityRecord`.

## Example Usage
```zig
const std = @import("std");
const rep = @import("biozig").reporting;

const sections = [_]rep.Section{
    .{ .title = "Results", .content = "Deterministic biological results." }
};

const report = rep.Report.init(
    "My Study", "Authors", "Abstract", 
    &sections, &[_]Figure{}, &[_]Table{}, &[_]Reference{}, 
    &[_]Figure{}, &[_]Table{}, 
    reproducibility_record
);

var out_buf = std.ArrayList(u8).init(allocator);
defer out_buf.deinit();

try rep.markdown.exportMarkdown(report, out_buf.writer());
```

## Limitations
- PDF generation relies on simple text translation or external engines (like pdflatex) depending on the exact build environment configuration.
- The layer does not support WYSIWYG editing.
